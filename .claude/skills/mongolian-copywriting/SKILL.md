# Mongolian Copywriting — 재창작과 검수문

## 전제: 몽골어가 원본이다

한국어 원고는 **의도의 설계도**이지 번역 대상이 아니다. 읽는 사람은 몽골어만 읽는다. 판단 기준은 하나 — 몽골 사람이 읽고 몽골 사람이 쓴 글이라고 느끼는가.

축자 번역의 실패는 눈에 잘 띄지 않아서 더 위험하다. 문법이 맞고 뜻이 통해도, 원어민에게는 "번역기 냄새"가 즉시 감지된다. 정서적인 글에서 그 이물감은 진심 자체를 의심하게 만든다.

## 몽골 운문의 핵심: 두운(толгой холбох)

몽골 시는 유럽 시와 반대로 **행의 끝이 아니라 행의 첫머리를 맞춘다.** 이것이 몽골 운문의 정체성이다.

```
Бүрэнхий байсан хорвоо гэрэлтэж      ← Бү
Бүүдгэр байсан наран мишээж          ← Бү
Гундаж удсан цэцгүүд өндийж          ← Гу
Гэрэл гэгээтэй хамт чи минь ирсэн билээ ← Гэ
```

위 4행은 실제 사례이며 정확한 AABB 두운이다. 이 구조를 알아보는 것과 모르는 것의 차이가 결과물 전체를 가른다. 상세 규칙·장르·어휘는 `references/mongolian-poetics.md`를 읽는다.

**회답 기법:** 상대가 과거에 준 시가 있으면, **같은 두운 음절을 되받아** 답시를 짓는다. 위 시에 답한다면 `Бү`와 `Гэ`로 시작하는 4행을 짓는다. 받는 사람이 자기 시를 알아보는 순간이 글 전체의 절정이 된다. 어떤 미사여구도 이보다 강하지 않다.

**두운은 억지로 맞추지 않는다.** 운을 맞추려고 어색한 단어를 밀어넣으면 즉시 티가 난다. 자연스러운 두운이 안 나오면 산문으로 쓰고, 그 사실을 검수문에 명시한다. **어색한 시보다 좋은 산문이 낫다.**

## 재창작 원칙

**화자의 기존 어휘를 이어받는다.** 화자가 과거에 쓴 몽골어 글이 있으면 그것이 문체의 기준선이다. 이미 쓴 이미지(예: `амьдралын минь гэрэл`, `түшиг тулгуур`)를 새 어휘로 갈아치우면 화자가 아니라 기계가 쓴 글이 된다. 기존 어휘를 뼈대로 두고 깊이를 더한다.

**친밀도를 어미로 만든다.** 부부·연인 사이는 `чи`(친밀한 너)이고 `та`(존칭)가 아니다. `хайрт минь`, `чи минь`처럼 소유 불변화사 `минь`이 붙을 때 온기가 생긴다. 과도한 존칭은 정중한 게 아니라 **차갑다.**

**모음조화를 지킨다.** 몽골어는 후설모음(а, о, у)과 전설모음(э, ө, ү)이 한 단어 안에서 섞이지 않고, 어미도 어간에 맞춰 선택된다(-аас/-ээс/-оос/-өөс). 이걸 틀리면 문법 오류 이전에 **귀에 거슬린다.** 확신이 없는 어미는 `needs_native_check`로 표시한다.

**그들의 실제 말투를 배척하지 않는다.** 두 사람이 실제로 로마자 표기(`Khairdaa ene horwood...`)나 이모지로 대화한다면, 그건 이 부부의 진짜 언어다. 전부 정통 문어 키릴로 정제하면 오히려 낯설어진다. 사적이고 장난스러운 씬에서는 그 질감을 의도적으로 살린다. 격식과 사적 친밀함을 씬마다 의도적으로 배분한다.

**이름 뜻풀이는 검증 후에만.** 몽골 이름은 대부분 의미가 있고 서사에 강력하지만, 틀린 해석은 선물을 망친다. 확신이 있는 것만 쓰고, 애매하면 쓰지 않는다.

## 한국어 검수문 작성

의뢰인이 몽골어를 읽지 못하는 경우, 검수문은 **번역이 아니라 감사 문서**다. 화면에 실제로 무엇이 쓰였는지 의뢰인이 알 수 있어야 한다.

검수문에 반드시 포함할 것:
1. 몽골어 원문 그대로
2. 직역에 가까운 정확한 뜻 (예쁘게 다듬지 않는다 — 의역하면 검수가 무의미해진다)
3. 사용한 기법 표시 — `[두운: Бү-Бү-Гэ-Гэ]`, `[ерөөл 형식]`, `[구어체]`
4. 의역·창작된 부분의 명시 — "한국어 원고에는 없지만 몽골어에서 자연스럽게 하기 위해 추가한 표현"
5. 확신이 낮은 부분 표시

검수문이 몽골어보다 예쁘면 잘못 쓴 것이다. 의뢰인이 승인한 내용과 아내가 읽는 내용이 달라지는 것이 최악의 실패다.

## 렌더링 요구사항 전달

몽골어 키릴에는 러시아어에 없는 **`Өө`와 `Үү`**가 있다. 많은 장식용 폰트가 이 글리프를 포함하지 않아 두부(□)로 렌더링된다. 엔지니어에게 다음을 반드시 통보한다:

- 폰트는 키릴 확장 글리프(`Ө ө Ү ү`)를 실제로 포함해야 한다 — Noto 계열이 안전하다
- `<html lang="mn">`, `charset="utf-8"` 필수
- 몽골어 문장은 같은 뜻의 한국어보다 **눈에 띄게 길다.** 고정 높이 박스에 넣으면 넘친다
- 헤드라인 최대 길이를 실제 확정 텍스트 기준으로 통보한다

## 출력

`bilingual.json` — 씬별 `headline_mn`, `body_mn`, `verse_mn[]`, `alliteration`, `headline_ko`, `body_ko`, `translator_note_ko`, `confidence`.

`confidence: "needs_native_check"` 항목은 최종 보고에서 사용자에게 **반드시 나열한다.** 원어민 확인이 필요한 곳을 숨기면, 검증되지 않은 문장이 그대로 상대에게 전달된다.
