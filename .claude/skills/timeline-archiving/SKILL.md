# Timeline Archiving — 기억의 정규화

흩어진 진술을 **단일 진실 원천**으로 만드는 절차. 이후 모든 작업은 이 파일 하나만 신뢰한다.

## 왜 이 단계가 먼저인가

작가가 글을 쓰기 시작하면 사실과 창작의 경계가 흐려진다. 연표를 먼저 못 박아 두면, 나중에 "이 문장의 근거가 뭐였지?"를 되짚을 수 있다. 개인사 콘텐츠에서 사실 오류는 미학적 결함이 아니라 **관계의 사고**다. 아이 생일이 하루 틀린 축하 페이지는 선물이 아니다.

## 절차

### 1. 진술 추출

원본 브리프에서 인물·날짜·사건을 뽑되, **사용자의 표현을 함께 보존한다.** "개구쟁이 남자아이"는 요약하면 정보가 사라지는 종류의 진술이다. 작가는 이런 표현에서 장면을 만든다.

### 2. 씬 ID 부여

시간순으로 `S01`, `S02`... 를 부여한다. **ID는 한 번 부여하면 절대 재배치하지 않는다.** 중간에 씬이 추가되면 `S04a`처럼 삽입하거나 끝에 붙인다. 팀원들의 산출물이 ID로 서로를 참조하므로, 번호를 다시 매기면 모든 파일이 어긋난다.

프롤로그는 `S00`, 에필로그는 `S99`를 쓴다.

### 3. 확실성 등급 표기

| 등급 | 조건 | 화면 표시 방식 |
|------|------|--------------|
| `confirmed` | 사용자가 단정적으로 진술 | 날짜를 그대로 표시 |
| `uncertain` | "~일 또는 ~일", "아마" | 날짜를 흐리게 처리하거나 "2019년 9월"로 축약 |
| `TODO` | 정보 없음 | 화면에 날짜를 쓰지 않는다 |

`uncertain`한 날짜를 화면에 단정적으로 박지 않는다. 당사자는 반드시 알아챈다. 확실하지 않으면 범위를 넓혀 표기하는 편이 안전하다 — "2019년 9월, 우리가 처음 만난 그 주"는 틀릴 수 없다.

### 4. 미디어 스캔

사진 디렉토리를 실제로 스캔한다. 존재를 가정하지 않는다.

```bash
find assets/img -type f \( -iname '*.jpg' -o -iname '*.jpeg' -o -iname '*.png' -o -iname '*.heic' \) \
  -printf '%p\t%s\n' 2>/dev/null | sort
```

파일이 있으면 촬영일자를 확인해 연표 배치의 근거로 삼는다. 파일명이 무의미할 때 EXIF가 유일한 단서인 경우가 많다.

```bash
# exiftool이 있으면
exiftool -q -DateTimeOriginal -FileName -ImageSize -T assets/img/* 2>/dev/null
```

HEIC(아이폰 기본 포맷)는 브라우저에서 열리지 않는다. 발견 즉시 JPEG 변환 필요 항목으로 보고한다.

**사진이 하나도 없어도 작업을 멈추지 않는다.** 파일명 규칙 `{YYYY}-{slug}-{nn}.jpg`를 확정해 배포하고, 전 씬을 플레이스홀더로 설계한다. 사진은 대개 마지막에 도착한다.

### 5. 질문지 작성

빠진 사실은 지어내지 말고 질문으로 만든다. **질문의 품질이 최종 결과물의 품질을 결정한다.**

좋은 질문은 감각적 디테일을 캐낸다. 사람은 감정을 요약해서 말하지만, 장면을 물으면 진짜 기억이 나온다.

| 나쁜 질문 | 좋은 질문 | 이유 |
|----------|----------|------|
| 첫 만남은 어땠나요? | 그날 어디서 만났고, 아내분이 무슨 옷을 입고 있었나요? 먼저 말을 건 쪽은 누구였나요? | "좋았다"는 글이 안 된다. "회색 코트"는 글이 된다 |
| 아이가 태어났을 때 기분은? | 아이를 처음 안았을 때 아내분이 뭐라고 하셨나요? | 인용된 한마디가 서술 열 줄을 이긴다 |
| 아내분은 어떤 분인가요? | 최근에 아내분이 하신 일 중, 나라면 못 했겠다고 생각한 게 있나요? | 추상적 찬사 대신 구체적 증거 |
| 미안한 마음이 있나요? | 미안한 순간이 떠오른다면, 그게 무슨 요일 몇 시쯤의 어떤 장면인가요? | 사과는 구체적일수록 진심으로 읽힌다 |

질문은 **한 번에 8개 이하**로 묶는다. 스무 개를 던지면 답이 오지 않는다. 서사에 가장 큰 구멍부터 우선순위를 매긴다.

각 질문에 "답이 없으면 어떻게 처리할지"를 함께 적는다. 사용자가 부담 없이 건너뛸 수 있어야 한다.

### 6. 출력

`timeline.json` — 씬 배열. 각 씬은 `id`, `date`, `date_confidence`, `type`, `title_ko`, `facts[]`, `media[]`, `status`, `open_questions[]`.
`assets.json` — 파일 경로, 크기, 촬영일, 매핑된 씬 ID, 변환 필요 여부.
`questions.md` — 우선순위 순 질문지.

## 증분 갱신

완벽한 연표를 기다리며 팀을 대기시키지 않는다. 확정된 씬을 먼저 배포하고, 답이 도착할 때마다 해당 씬만 갱신한 뒤 변경분을 알린다. 전면 재작성은 하류 팀원의 작업을 무효화한다.
